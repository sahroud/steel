# SAHROUD STEEL — قراردادهای موازی بارگذاری، حل‌گر و تقاضای اعضا

وضعیت این سند: قرارداد نرم‌افزاری / پیش‌نویس پیاده‌سازی؛ نه تأیید مهندسی.

## ۱. قرارداد شواهد حالت بار

ماژول `js/load-case-evidence-contract.js` با API زیر در دسترس است:

```js
SteelLoadCaseEvidenceContract.audit({ loadCases: [...] })
```

هر حالت بار باید دست‌کم شناسه یکتا، نوع بار، دسته، واحد از فهرست مجاز، دستگاه مختصات، قرارداد علامت، مقصد اعمال، مقادیر عددی و منبع شامل سند، ویرایش، محل دقیق در سند و مرجع/تهیه‌کننده داشته باشد.

انواع ثبت‌شده فعلی: `nodal`, `member_point`, `member_uniform`, `surface`, `support_settlement`, `temperature`, `crane_wheel`, `other`.

واحدهای پذیرفته‌شده صرفاً برچسب‌های مجاز قرارداد هستند؛ این ماژول تبدیل واحد انجام نمی‌دهد. مقادیر باید پیش از انتقال به حل‌گر به واحدهای سازگار تبدیل و کنترل شوند. نبودن داده با صفر جایگزین نمی‌شود. این ماژول بار آیین‌نامه‌ای تولید نمی‌کند و هیچ ضریب ترکیبی پیشنهاد نمی‌دهد.

## ۲. پیشنهاد مدل برای حل‌گر سه‌بعدی

ماژول `js/solver-model-proposal-adapter.js` با APIهای زیر در دسترس است:

- `audit(model, options)`: ممیزی توپولوژی، شناسه‌ها، مختصات، اعضا، تکیه‌گاه‌ها، آزادسازی‌ها و ارجاع مقطع.
- `buildProposal(model, options)`: ساخت کپی پیشنهادی غیرمخرب پس از عبور از ممیزی.
- `solveExplicit(model, options, {runSolver:true})`: اجرای صریح حل‌گر موجود، فقط پس از عبور ممیزی و تأمین تابع `sectionResolver`.

این مبدل هرگز `SteelProject.loadData` را فراخوانی نمی‌کند و مدل فعال پروژه را تغییر نمی‌دهد. هیچ حل خودکاری با بار ناقص انجام نمی‌شود؛ `requireExplicitMemberLoads` اجباری است. برای هر شناسه مقطع خارجی، نگاشت صریح و قابل ردیابی لازم است. هندسه متغیر فاقد ایستگاه‌های هندسی کافی رد می‌شود و به مقطع منشوری معادل تبدیل نمی‌گردد.

این مبدل به‌تنهایی اثبات نمی‌کند که دستگاه مختصات، واحدها، شرایط مرزی، خواص مقاطع یا بارگذاری از نظر مهندسی صحیح‌اند. امکانات و محدودیت‌های خود حل‌گر نیز باید جداگانه بررسی شوند.

## ۳. قرارداد نیروهای همزمان اعضا

ماژول `js/member-simultaneous-action-contract.js` ورودی نتایج تحلیل را با ساختار زیر ممیزی می‌کند:

```js
{
  memberIds: ["M-01"],
  cases: [{
    caseId: "ULS-01",
    equilibriumOk: true,
    members: [{
      memberId: "M-01",
      endI: { Fx: 0, Fy: 0, Fz: 0, Mx: 0, My: 0, Mz: 0 },
      endJ: { Fx: 0, Fy: 0, Fz: 0, Mx: 0, My: 0, Mz: 0 }
    }]
  }]
}
```

اعداد صفر در مثال فقط جای‌نگهدار ساختار هستند و داده پروژه نیستند. هر دو انتهای هر عضو باید هر شش مؤلفه را از همان حالت تحلیل داشته باشند. تعادل باید صریحاً برقرار باشد و پوشش اعضا برای تمام حالت‌ها کامل باشد. قرارداد، مؤلفه‌های مستقل بیشینه/کمینه را با هم ترکیب نمی‌کند؛ ظرفیت، کمانش یا طراحی عضو را هم محاسبه نمی‌کند.

## ۴. جایگاه در برنامه و آزمون

سه اسکریپت در `steel2/index.html` پس از بارگذاری حل‌گر و رجیستری ترکیبات و پیش از آزمون‌های بازگشتی ثبت شده‌اند. سه آزمون مستقل ماژول‌ها به `engineering-regression-tests.js` افزوده شده‌اند.

نتایج خودآزمون‌های ماژول در زمان افزودن:
- قرارداد شواهد بار: ۹ از ۹
- آداپتور پیشنهاد مدل حل‌گر: ۹ از ۹
- قرارداد نیروهای همزمان عضو: ۸ از ۸

این نتایج، آزمون نرم‌افزاری داخلی هستند؛ نه آزمون مرورگر، نه تطبیق با یک حل‌گر مستقل و نه کنترل آیین‌نامه‌ای یا تأیید نقشه. برای اتصال عملیاتی به پروژه فعال، هنوز باید نگاشت داده‌های واقعی `structuralModel`، مصالح/مقاطع، آزادسازی‌ها، بارهای صریح و تکیه‌گاه‌ها با یک مدل آزمایشی معتبر و کنترل مستقل انجام شود.
