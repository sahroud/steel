# پل ترکیب بار به تقاضای ایستگاهی اعضا

## هدف
ماژول `SteelMemberDemandCombinationBridge` ضرایب ترکیب بار صریح و مستند را روی بردارهای شش‌گانه هم‌زمان هر ایستگاه اعمال می‌کند. این ماژول فقط «پیشنهاد تقاضای ترکیبی خطی» تولید می‌کند؛ بار تولید نمی‌کند، حل‌گر را اجرا نمی‌کند و طراحی را تأیید نمی‌کند.

## API
```js
SteelMemberDemandCombinationBridge.build(
  demandPackage,
  { loadCases: [{ id, category }], combinations: [{
    id, factors: { "D-01": 1.2, "W-01": 1.0 },
    source: { code, edition, clause, document }
  }]},
  {
    sameModelRevision: true,
    sameGeometry: true,
    sameSupports: true,
    sameStiffnessModel: true,
    linearElasticFirstOrder: true
  }
)
```

فرض‌های تحلیل باید توسط مهندس مسئول صریحاً اعلام شوند؛ این اعلان‌ها به‌صورت مستقل راستی‌آزمایی نمی‌شوند. رجیستری ترکیب بار نیز کامل‌بودن شناسه‌ها، ضرایب و مرجع آیین‌نامه‌ای را کنترل می‌کند.

## کنترل‌های تطابق
- بسته تقاضا باید موفق و غیرتأییدشده باشد.
- هر حالت مرجع ضریب باید در بسته تقاضا حضور داشته باشد.
- برای هر عضو، تمام حالت‌های مورد استفاده باید موجود باشند.
- تعداد/شناسه ایستگاه‌ها، مختصات محلی و فیزیکی، شناسه قطعه و محورهای محلی باید بین حالت‌ها یکسان باشند.
- هر ایستگاه باید شش مؤلفه هم‌زمان N، Vy، Vz، T، My و Mz را داشته باشد.
- قطعات اعضای متغیرمقطع جدا باقی می‌مانند.

## محدودیت‌های ایمنی
- هیچ ضریب آیین‌نامه‌ای خودکار ساخته نمی‌شود.
- هیچ مؤلفه‌ای از ایستگاه یا حالت دیگری برای ساخت بردار ترکیبی قرض گرفته نمی‌شود.
- پوش مؤلفه‌ای ساخته نمی‌شود.
- اثرات غیرخطی، مرتبه دوم، تغییر تکیه‌گاه، ظرفیت، کمانش، اندرکنش، خستگی، اتصالات و کنترل آیین‌نامه‌ای محاسبه نمی‌شوند.
- خروجی همیشه `designApproved:false` و `readyForCodeDesign:false` است.
- selfTest فقط آزمون نرم‌افزاری ماژول است، نه اعتبارسنجی مستقل مهندسی.

## وضعیت
نسخه اولیه: ترکیب خطی شش مؤلفه در ایستگاه‌های هم‌تراز با کنترل سخت‌گیرانه توپولوژی و فرض‌های تحلیل.
